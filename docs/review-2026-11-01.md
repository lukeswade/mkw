### 2. Check citations after synthesis

- **Measured today.** I compared every number in a cited sentence with the
  stored evidence for the sources it cites, which is what synthesis was
  shown. Across 8 reports:
  - 14 of 150 numeric cited sentences had a number absent from the cited
    evidence.
  - On reading them, 11 are genuine: 7.3% of numeric claims. Examples:
    - Time-Sert "~40%" and Helicoil "~25%" pull-out strength, in a repair
      report, with no source for either;
    - "WER ~3.2%" for Whisper Large V3;
    - "14.61GB of VRAM";
    - a ROCm override value credited to [4] when it comes from [75].
- That is a lower bound. A number that appears in the source but for a
  different subject passes a string check. Matt's 10-15 report credits
  "~24 tok/s" to Qwen3-Coder on an RX 6700 XT, citing [10], which measured
  Qwen3.6-35B-A3B on an RTX 3080 Ti.
- **Do:** after reconcile, for each numeric cited sentence:
  - **String pass, no model:** is the number in the cited evidence?
  - **Absent:** look for it in the other kept sources. If exactly one has
    it, re-cite. If none, one model call rewrites the sentence without the
    figure or marks it unverified.
  - **Subject check:** one batched model call checks the numbers that are
    present for the right subject (about 10 sentences per call).
  - **Report footer:** state what was checked, re-cited and removed.
- Cost: under a second for the string pass, about 1–2 minutes for model
  calls. The same code is metric #1 of the harness in item 4.

### 3. Write the report section by section from an evidence bank

- **Today:** the draft is one call with every source's notes and up to 8
  facts. In Matt's depth-9 run that was two synthesis calls totalling 92.9K
  prompt tokens for 82 sources. The same report:
  - gives three speed ranges for one setup (3–12, ~20–40, 40–65 tok/s);
  - gives two llama.cpp build floors: b8765+ from a source and b9615+,
    which is Matt's own baseline from his question, without saying which
    is which;
  - makes a June source's DeepSeek-Coder-V2 Lite the primary coding pick
    over newer models in the pool;
  - misattributes the 24 tok/s figure from item 2.
- **The literature agrees on the remedy:**
  - WebWeaver (arXiv 2509.13312): an outline whose sections cite a memory
    bank of evidence, then a writer that drafts one section at a time from
    only that section's evidence. It is reported to cut long-context and
    citation errors.
  - The on-device 4B study (arXiv 2607.12257): faithfulness tracks how much
    of each source the writer sees (0.45 → 0.58 when per-source exposure
    went from 400 to 1,500 characters). Coverage tracks retrieval recall.
- **Do:**
  1. Notes add `subject` and `conditions` to each key fact (e.g. "Qwen3.6-35B-A3B",
     "RTX 3080 Ti, llama.cpp --n-cpu-moe 25").
  2. One outline call maps facets, candidates and premises to sections,
     each with its fact ids.
  3. Sections are written concurrently, each from its facts, its sources'
     best passages and their dates. The prompt prefers the newest evidence
     and flags older figures.
  4. TL;DR and recommendations are written last, from the sections.
  5. A consistency pass flags one subject and metric with conflicting
     values.
- Behind a setting. Judge it by item 4 on stored runs via
  `scripts/resynth_ab.py` (no re-search). Also worth one arm each:
  synthesis with thinking on, and Qwen3.8-27B as the writer (memory permitting).

## Built: the citation check (11-01, uncommitted, not deployed)

Luke said "set concurrency to 5 and build the citation check".

- **Concurrency:** `llm_concurrency` 3 → 5, saved with `save_settings` in
  the container. Runs reload settings, so it applies from the next run.
- **Citation check:** `app/research/citecheck.py`. It runs after
  reconciliation and before the closing sections, in a run and in
  Re-synthesize. Its counts go into the run's stats as `citation_check`.
  It is on by default, with a switch under Settings → Search.

**How it works.**
1. A string pass, with no model call, finds cited prose sentences whose
   figures or numbered names appear in no cited source's notes, facts or
   quotes. Number, unit, version and name spellings are normalised;
   roundings and another name for the same model count as a match.
2. Each flagged sentence goes to the model with the cited sources' notes,
   plus up to three other kept sources that state the missing figures. The
   model answers keep, recite or rewrite.
3. Code applies a re-cite only if every figure in the sentence is then
   stated by what it cites, and a correction only if its figures appear
   with their units, it keeps a citation, and it stays 0.4–1.6× the
   original length.
4. **Never sent:** headings, tables, quotes, the Open questions section,
   questions, sentences about what is unknown, and sentences whose only
   unmatched figures come from the question.
5. At most 30 sentences per report. Any failure keeps the document as
   written.

**Related fix.** Grouped markers like `[2, 25]` are now read as citations by
`cited_ids`, `validate_citations` and the web renderer, through one parser in
`storage.py`. Two stored reports had listed a cited source under "Researched
but not used" because of this.

**Dry runs** on eight stored reports, with the real model and nothing
written:

| | Cited sentences with figures | Flagged | Re-cited | Corrected | Kept | Refused by code | Harmful on review |
|---|---|---|---|---|---|---|---|
| First design | 328 | 55 | 8 | 21 | 0 | 26 | 10 of 29 |
| As built | 288 | 24 | 6 | 8 | 5 | 5 | 0 of 14 |

- **First design.** The harmful changes were:
  - a rewritten Open Questions item;
  - "P99.9 remains less documented" turned into a claim about P99;
  - the asker's own engine and baseline build removed;
  - "E2E" read as a figure;
  - a re-cite that left "15 of 19 benchmarks" uncited;
  - "12-15GB" accepted from "12B-15B parameters";
  - naming nitpicks.

  Each became a rule in code and a test.
- **As built,** checked against the sources:
  - Matt's invented Time-Sert part number "4412E-111A" (no source in the run
    has it) became "4412E (with 'A' suffix for aluminum)", as source [30]
    says;
  - the Time-Sert/Helicoil 40%/25% figures re-cited to the source that
    states them;
  - an MTP speed-up re-attributed from "Qwen3.8" to "Qwen3.6", as its source
    says;
  - "~20-65 tok/s" became "~6-65 tok/s [33, 54, 56]", matching [54]'s 6 tok/s

  - "262K context" re-cited while keeping [5] for "15 of 19 benchmarks".
- **Missed:** Fermyon Spin "2.6" stays, because the model's corrections
