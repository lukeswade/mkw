## Proposals not built

1. **Round one spends the whole budget at depths 4–6.** With reads keeping
   87%, round one fills the source cap and gap analysis never directs a
   round (depth 4: 1 round of 4; depth 9: 3–4 of 8). Capping round one at
   ~60% of the budget would let the facet machinery steer the rest. Needs a
   paired A/B (two depth-4 runs on one question, ~40 min).
2. **Numbers attached to the wrong model.** Matt's report credits
   "~24 tok/s" to Qwen3-Coder 30B-A3B citing a source about Qwen3.6-35B-A3B.
   A post-synthesis check of each cited number against its source's notes
   would catch this class; cost ~1–2 minutes a run.
3. **Bullet lists of constraints become facets.** A brief written as
   "Hardware:\n- CPU: …\n- GPU: …" would get one facet per spec line,
   searched and then reported unresearched. Not yet seen in a run.
4. **Review backlog 2026-09-09:** #9, #11, #13, #17, #19, #22, #23, #26–#28
   remain open, all low impact; #14, #16, #18, #20, #24, #29 are fixed by
   later work.
5. **Port 8090 is open to the LAN with no password** (`WEB_PASSWORD` empty);
   mattkwade.com is behind Cloudflare Access.

## Models

No model change recommended. Qwen3.6-35B-A3B-oQ4e-mtp, nomic modernbert
embeddings and jina-reranker-v3.5 remain the right set (survey 10-16,
reranker eval 10-16); oMLX 0.7.1rc1 is the newest release. One experiment
is worth running: oMLX 0.7.1rc1 can hand Qwen3.6 to **Splash** (DFlash2
speculative decoding, JSON Schema output, batching, honours
`enable_thinking: false`), claimed 1.7× decode on this model. Decode is about
half of a run, so it is the largest speed lever available — unmeasured on an
M4 Pro and with the oQ4e quant. Measure with the 12-page notes benchmark
(baseline: 229 s mean at concurrency 3) before keeping it.

## Splash, measured (after the review, at Luke's request)

oMLX 0.7.1rc1 serving Qwen3.6-35B-A3B-oQ4e-mtp through Splash 1.3.2 with the
`incoai/Qwen3.6-35B-A3B-DFlash2` draft, against oMLX's own MLX engine. Same
12 pages through `take_notes` (strict schema, thinking off, concurrency 3),
two or more arms each, results in `data/eval/notes-bench.jsonl`:

| | wall (12 pages) | evidence quotes | verbatim |
|---|---|---|---|
| MLX, presence_penalty 1.5 (mlx_lm: last 20 tokens) | 230.6 / 226.3 s | 85 / 88 | 98% |
| Splash, 1.5 (every output token, as vLLM) — 4 arms | 148–161 s | 76–78 | 95% |
| Splash, 0 sent by the request — 3 arms | 153 / 153 / 153 s | 86 / 85 / 81 | 95% |

Splash is 1.5× faster on the notes step (per-request decode 30–57 tok/s
against 15–19; prefill about the same), with no failures; thinking-off and the
JSON schema are honoured, and a depth-1 run went end to end cleanly. The
model's presence_penalty of 1.5 means something different there, so mkw now
sends 0 on its structured calls (`3d8bf25`); free text keeps the server's
setting. Splash holds ~22 GB (plans 26 GB with the draft) against ~21 GB for
the MLX engine; no memory-guard refusals during the arms.
